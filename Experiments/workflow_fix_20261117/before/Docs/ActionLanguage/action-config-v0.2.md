## 1. 输出目标与边界

输入明确的中文动作描述，模型在宿主绑定的 Yukikaze 资源目录内预测：使用什么资源、如何编排，以及每次动作的具体参数。宿主将配置确定性展开为原生参数关键帧，校验后播放。

首个参数预测版本建议最多 2 个动作条目、2 个步骤，每个动作 1～3 个完整循环。动作资源集合先开放完成参数化标定的少量资源，再逐项扩展。现有 12 类动作不能仅凭代码里有名称就全部视为已标定。

首版可调项：资源允许的幅度增益、完整循环时长、资源定义的保持比例。逐通道独立幅度、任意新关键帧／曲线残差、开放式持续动作和跨周期同步作为后续扩展，不应假装已被这三个参数覆盖。

## 2. 结构示例

描述：“轻轻点头两次，第二次慢一点，然后眨一下眼。”

```json
{
  "version": "action-config.v0.2",
  "decision": "execute",
  "steps": [
    {
      "actions": [
        {
          "resource_id": "nod.basic",
          "cycles": [
            {"duration_ms": 800, "controls": {"amplitude_scale": 0.55, "hold_ratio": 0.15}},
            {"duration_ms": 1100, "controls": {"amplitude_scale": 0.55, "hold_ratio": 0.15}}
          ]
        }
      ]
    },
    {
      "actions": [
        {
          "resource_id": "blink.full",
          "cycles": [
            {"duration_ms": 600, "controls": {"hold_ratio": 0.20}}
          ]
        }
      ]
    }
  ]
}
```

以上资源 ID 和数值仅演示字段关系，不是已经标定、经视觉确认或当前可执行的配置，也不表示“慢一点”只有一个正确毫秒值。实际可调范围、相位定义、资源内容和原生可执行性必须在实施时验证。

非执行示例：

```json
{"version":"action-config.v0.2","decision":"none","steps":[]}
```

## 3. 字段定义

| 字段 | 语义与约束 |
| --- | --- |
| version | 固定为 action-config.v0.2 |
| decision | execute / none / unsupported / ambiguous |
| steps | 有序步骤；非 execute 必须为空；execute 首版 1～2 步 |
| actions | 同一步同时开始；每步非空；全包最多 2 个动作条目 |
| resource_id | 已绑定目录中可训练、可执行资源的稳定 ID；不能生成文件路径或任意 Cubism 参数 ID |
| cycles | 按顺序执行的完整循环列表，长度 1～3；长度就是次数，不另设 count |
| duration_ms | 本次完整循环的整数毫秒数，包含运动、保持和回位；建议协议外层 240～3000ms，资源及编译约束可更严格 |
| controls | 对应资源允许的连续参数字典；未知、不适用或缺少必需参数应拒绝 |
| amplitude_scale | 相对资源参考姿态的幅度增益，仅在资源声明支持时出现；取值范围由资源标定 |
| hold_ratio | 本次循环中资源所定义保持阶段占比，取值和适用范围由资源定义；它不是跨动作等待时间 |

持续时间为各循环 duration_ms 的总和。同一条动作的循环间不附加隐含间隔。下一步等待上一步最长动作的全部循环结束；较短动作在剩余时间保持资源回收姿态。最后只进行一次播放器释放。

仅允许对同一步内互不冲突的 actions 按稳定资源顺序规范化。禁止改变 steps 或 cycles 顺序；“第二次”对应 cycles[1]，不能排序、合并或丢失。

数据层外部约束中的 action_index 统一定义为：先规范同一步动作顺序，再按 steps 顺序展开全包动作得到的零基索引。cycle_index 和 reference_cycle_index 是该动作内部的零基循环索引。规范化或迁移时必须同步重映射外部约束、数字区间归属和参数标签，不能只排序动作数组。运行时不把外部约束索引当作任意可执行字段，约束及其来源由宿主保存和校验。

两个并行动作只要写入相同原生通道，首版拒绝，不按数组顺序覆盖。若描述要求逐次同步、偏移开始、一直保持到外部事件或缺少支持的动作，应返回 unsupported；无法明确动作或关系时返回 ambiguous。不要将模型内部无效输出伪装成 none。

## 4. 参数化资源必须包含什么

资源目录是训练、校验、编译和评估共用的真源。每项资源至少提供：

- resource_id、语义说明、完整周期定义、适用角色、内容哈希、标定状态。
- 实际使用的原生通道、参考值、回收值、Core 范围、起姿容差和参数归属。
- 原始曲线／可恢复资源、相位拓扑、各通道在不同相位内的关键点。
- 可调字段、单位、标定范围、默认值、固定字段、损失 mask、相对描述的标注规则。
- 字段到曲线的确定性映射，以及字段组合的额外约束。
- 经检查的默认配置和边界配置；可追溯的视觉标定记录。

原始 .motion3.json 可以作为资源素材；导入时仍需提取实际通道、解释周期与相位并标定参数化方式。现有 motion 文件名和情绪名称不自动构成自然语言训练标签。

### 幅度的参考值

仅对声明可缩放的通道使用：

```text
native_value = reference_value + amplitude_scale × resource_delta
resource_delta = base_curve_value - reference_value
```

不能把绝对参数值统一乘幅度：例如眼睛参考开度为 1，直接乘会破坏睁眼基准。资源可以声明某些通道固定、某些随主幅度缩放，后续再开放独立控制。blink.full 的完全闭合和恢复睁眼固定，不输出幅度字段，也不训练该项回归。

### 时长与保持阶段

每个支持 hold_ratio 的资源必须声明保持哪个姿态，以及全部通道随该比例变化的时间映射。建议使用“进入 → 保持 → 返回”三相位；若资源需要多次摆动或其他相位，必须另外明确，不能统一套公式。

对三相位资源，可固定剩余运动时间在进入／返回之间的比例 alpha，令：

```text
hold_time = duration_ms × hold_ratio
enter_time = (duration_ms - hold_time) × alpha
return_time = (duration_ms - hold_time) × (1 - alpha)
```

每个相位内部关键点按该资源自己的映射展开。alpha 来自标定，首版不必由模型预测。多通道共享相位定义，但可有各自的相位内曲线；不能只移动主通道而让身体或眼睛错位。若支持零保持，应明确合并相同时间、相同数值的冗余关键点；不同值同刻或剩余段过短仍拒绝。

连续参数单独落在范围内不代表组合合法。duration、hold、幅度和循环数必须联合检查。输出层采用有界参数化也不能替代真实编译。

## 5. 编译到原生 v0.1

现有参数化编译入口为 ActionConfigCompiler，底层继续使用 ActionContract、ActionPlayer、Live2DActionAdapter。以下是应满足的编译约束；当前实现会合并过短的 hold 段，尚不能承诺任意合法配置的保持比例都原样呈现，教师接入时需核对实际视频与展开配置。

1. 严格检查版本、重复键、未知字段、非有限数、整数、数量与非执行结构。
2. 校验宿主绑定的资源目录、参数 schema 和角色配置；按宿主模式检查资源状态。正式执行只使用已标定资源；标定／人工预览可使用宿主登记的候选资源，仍须验证真实 Core 范围、参数归属和全部执行硬约束，并标明尚未验收。来自模型的配置额外核对该模型 manifest 的训练覆盖；人工冷启动不以“已经有新模型”为前提。
3. 逐动作、逐循环读取预测参数，按对应资源映射生成通道曲线；循环回位后衔接下一个循环。
4. 检查参考姿态兼容性、并行通道冲突；生成显式等待／保持点，防止后置动作提前插值。
5. 合并相同时刻不同通道；检查曲线及整包至少 80ms 参数段、最多 32 个关键时刻、16 个控制参数、10 秒控制阶段等既有约束。
6. 使用现有原生校验器整包验证，再在实际提交边界复核起姿、角色和会话代次。

不允许把 duration_ms、amplitude_scale 等重新量化成 slow/normal/fast 或 small/normal 后交给旧编译器；这会丢失本次训练目标。允许抽取复用旧编译器的严格解析、时序拼接和校验逻辑。原生参数值、时刻和资源展开后的实际配置必须可追溯。

非法组合返回编译错误或重新产生有明确记录的候选；不静默减少次数、修改显式时长、删除动作或放宽 80ms 下限。ms 整数化应采用固定规则并在整数化后再次验证；普通预测浮点归一化不表示可覆盖用户精确数字。

标定、评审、正式执行模式由宿主选择，不是模型输出字段。候选资源的试播不自动成为训练金标准；资源映射完成标定后，相关候选应在最终绑定版本下重新校验／必要时回放确认，再进入合格参数集，避免标定和采数互相等待。

## 6. 精确数值与相对描述

“第二次慢一点”是一项相对约束，应保存两个循环的实际时长，以及可验收的最小差异规则。实际幅度和时长可以有多个合理答案，标注策略应解释默认值、偏好和允许区间。

“第二次用 0.6 秒”则需要将文本中的数值区间关联到正确动作、正确 cycle、正确字段，再确定性换算为 600ms。时间单位换算可以由程序处理；归属不能用“抓到一个数字就填所有循环”代替。

建议分两阶段开放：先训练定性及相对参数预测；再加入数字区间与目标字段关联能力。未实现／未验收精确数值能力时，对这类输入明确返回不支持，不用回归近似值假装精确。显式要求违反资源或原生约束时返回不支持；模型推理内部矛盾／输出非法属于技术错误，不应伪装用户语义。

## 7. 版本绑定与兼容

宿主绑定 capability_profile、resource_catalog_version、parameter_schema_version、label_policy_version 及内容哈希；这些标识不是模型自由预测字段。模型输出的资源选择和参数通过服务响应 envelope 与这些标识关联。

原生 profile、参数维度、资源意义或曲线变动均须有版本变化及兼容评估。候选参数变体不改变共享资源，只新增候选及配置哈希。旧卡回放取当时实际配置和可恢复资源快照，不能重新推理或套最新资源。

固定资源分类头只能选择训练目录中的资源。增加资源或改变参数意义后，需要目录登记、标定、数据补充与训练／兼容验证；本方案不承诺零样本理解任意新资源。资源特征条件化、动态资源检索或任意曲线生成可另立后续方案。

旧 action-plan.v0.1 保留为兼容协议。迁移工具可以把旧计划展开为某个历史模板的默认配置并标为“派生候选”，但未经对应审核不可标为参数真值。现有 v0.1 与 v0.2 检查点分别存储，禁止仅改版本字符串冒充另一种模型。
