# 第 9 轮训练流程修复

教师直接生成描述与配置、独立观看回放审核，再监督训练本地模型，这条主线是合理的。本次发现的问题主要出在标签、编译回放及训练入口没有严格对应；继续增加训练轮次不能消除这些问题。修复已接入正式共享代码，修改前原文件在 `before/`，哈希在 `before_manifest.json`。

## 已修复

1. 指令和角色台词混用：Unity UI、API、候选、导出、训练及评估贯通 `input_role`。新训练使用角色前缀；旧权重不被错误加前缀。
2. 错误预测被“修好”后执行：移除冲突时换成其他资源、空执行改成 none 的行为。技术错误独立返回 422，保留拒绝前配置和约束审计，不制造语义标签。
3. 数字与标签不一致：明确次数、时长、逐次关系及引用进入校验；未覆盖作用域如近似/上下限保留 unresolved。普通“一边/一点/一起”等惯用语不作数字拦截。此解析器仍是有限语法，不证明任意自然语言意图。
4. 标签 hold 与实际播放不一致：过短的正 hold 不再被吞掉，资源缺 hold 端点时明确拒绝。当前 look_around 正 hold 无法表示，要求 0；没有偷改历史资源版本。
5. 录像不能证明完整：固定 30fps，记录实际播放器时间和 Cubism 参数，包含动作及回位，关闭编码器后才完成。取消、替换及故障不会冒充自然完成；批次完成回调不再重入销毁当前会话。批次初始化失败正确清除运行状态。
6. 回放覆盖与取景：新候选保留父候选，旧录像不覆盖。录像取景由裁切半身改为 720×840、固定相机完整角色范围，为手部动作留空间。
7. 脏数据与泄漏入口：来源分别标记历史合成、AI 视频审核、AI 非执行语义审核；程序核验真实证据再冻结。固定语义族/组/同文/父候选切分，禁止测试来源回流。AI 审核不以人工 keep 为条件。
8. 训练与上线混在一起：prepare/validate/train/evaluate 独立。训练只接冻结 manifest，只写新目录；按真实预测资源评估，每 epoch 留存验证预测。没有自动 ready、覆盖默认权重或回滚删除目录。
9. 人设文档的错误建议：修正 cheer 幅度越界、blink 时长超限、同侧歪头被称作左右摆动、尾巴意象被当作可执行能力。

## 验证

- 共享 Python 最终组合：23 项训练入口、35 项证据校验、17 组推理/真实临时 HTTP 回归全部通过。测试 accepted 记录都是显式夹具，不计入真实训练池。
- Unity 共享源码编译成功，0 错误；16 项真实编译规则检查通过。
- 真实回放验证覆盖单动作、串行、并行、非执行、短 hold 拒绝、输出不可覆盖、实际闭眼参数、尾段外部取消和角色字段保持。结果见 `reports/unity_workflow_check.json`。
- 视频独立全解码及逐帧核验见 `reports/real_recording_evidence_check.json`，视觉检查说明见对应 smoke 报告。技术回放通过不代表资源自然度或训练审核通过。
- 最终运行时加载第 9 轮冻结权重，对 28 条诊断样本实测：19 条技术拒绝、6 条决策正确，仍有 2 条非执行误执行。见 `reports/final_round9_diagnostic.json`。该诊断不是训练集独立性已证明的发布验收，更不是新模型提升。
- `reports/final_inventory.json` 记录正式代码变更和第 9 轮权重/原始语料保持不变的 SHA256 核验。

## 当前边界

没有启动新训练、替换第 9 轮权重、重启原服务或批准旧语料；没有真实 AI accepted 样本被补造。共享 Python 在新启动的进程中生效。新录像及测试输出只在本实验目录，历史录像原样保留。

教师 API 与自动轮次调度尚未实现；历史语料仍需逐项复核来源、固定切分和真实编译/视觉证据。除 blink 外的资源仍是候选，不能凭编译成功认定正式标定完成。先按修复后的入口得到可信数据，再做下一轮训练与版本比较。

实际使用方式见项目 `Docs/ActionEncoderTraining.md` 与 `Tools/ActionEncoder/training_workflow.md`。
