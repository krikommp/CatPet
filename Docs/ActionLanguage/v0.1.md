# Pet 动作描述协议 v0.1

状态：2026-11-16 设计草案。协议、Schema 和示例已落盘；解析器、播放器、字幕 UI 与 AI 接口尚未实现。本次不修改 Unity 场景或运行脚本。

## 1. 要解决的问题

AI 读取当前角色的能力表，输出少量“目标参数值 + 到达时间”。本地播放器在每个渲染帧计算连续姿态，再交给 Live2D。没有对应的预制 motion 文件也能编排动作，但输出只能使用实际存在且已开放的控制参数。

第一版采用 JSON，不增加自定义文本语法。设计分为两份数据：

- **能力表**：本地持有，描述模型参数、真实范围、默认值、含义的确认程度，以及哪些参数允许前台控制。
- **动作包**：AI 生成，引用能力表版本，并给出稀疏的绝对目标值和时间。

参数 ID 与数值直接使用该模型的原生单位。不要预设所有值都是 0～1，也不要把旧 Canvas 的 `ear_l`、`arms_mode` 等字段直接当作 Live2D 参数。需要跨角色通用指令时，再在能力表中增加经过验证的语义映射。

## 2. 最小动作包

```json
{
  "version": "0.1",
  "profile": "natori-demo.v1",
  "duration_ms": 1800,
  "subtitle": "我在听，你接着说。",
  "frames": [
    { "at_ms": 350, "values": { "ParamAngleX": 8, "ParamAngleZ": -6 } },
    { "at_ms": 1000, "values": { "ParamAngleX": 8, "ParamAngleZ": -6 } },
    { "at_ms": 1600, "values": { "ParamAngleX": 0, "ParamAngleZ": 0 } }
  ]
}
```

这个例子的意图是“小幅调整头部姿态，停留，回正”。参数 ID、范围和默认值已从 Natori 的 SDK 实例读取；这组组合的视觉效果尚未播放验证，正负朝向也没有完成视觉标注。它是待验证的动作草案。

| 字段 | 规则 |
| --- | --- |
| `version` | 必填，固定 `0.1` |
| `profile` | 必填，原样复制宿主提供的能力表标识；不能用展示名代替 |
| `duration_ms` | 必填，80～10000 的整数，表示动作控制阶段的长度，不含结束后的 200ms 释放 |
| `subtitle` | 可选，1～300 个 Unicode 码点的纯文本；不解析富文本、指令或路径 |
| `frames` | 必填，1～32 项，按 `at_ms` 严格递增 |
| `at_ms` | 相对动作开始的目标到达时刻，整数，至少 80ms，且不超过 `duration_ms` |
| `values` | 本帧的绝对目标值；键为真实参数 ID，值为有限数值；不是相对前一帧的加减量 |

第一版没有 `emotion`、`wave`、`priority`、`spring`、`loop` 或任意表达式字段。未知字段拒绝，不猜测其含义。动作包只描述一次有限时长的演出。

## 3. 时间和稀疏关键点的精确定义

### 起点与插值

完整动作包通过全部校验后，在下一次本地合成阶段原子提交，才令动作时钟为 0。网络请求时间、模型生成时间和 JSON 接收时间不计入动作时长。

对本包出现过的每个参数，本地自动添加一个零时刻关键点，值取提交前实际使用的合成值（物理计算之前）。AI 不输出 `at_ms: 0`，也不猜测初始姿态。首次启动时没有合成历史，则使用当帧基线值。

每个参数独立在自身相邻关键点之间插值，统一使用：

```text
u = clamp((t - t0) / (t1 - t0), 0, 1)
s = 3u² - 2u³
value(t) = v0 + (v1 - v0) * s
```

`at_ms: 350` 的意思是在 350ms 时曲线到达目标，不是在 350ms 才开始移动。第一版不在这条曲线后再串接会延迟到达的弹簧；需要过冲时可显式增加关键点。

这定义的是连续曲线。实际低帧率可能跨过某个时间点，播放器按当前时间求值，不补播过时的帧。动画时钟使用本地单调时间，不受游戏 timeScale 影响；宿主显式暂停时，动作和释放阶段的时钟都冻结。

### 省略不等于停住

某一帧没有某参数，表示**没有为该参数新增关键点**。它仍沿自己的曲线运动。需要保持姿态，就为该参数写两个相同值、不同时间的关键点。

上例中两项头部参数在 350ms 到达目标，保持至 1000ms，然后在 1600ms 回到 0，保持至 1800ms。之后进入 200ms 释放阶段。

一个参数最后的显式关键点之后，保持最后目标直到 `duration_ms`。完全未出现在动作包中的参数继续由本地基线驱动。所有出现过的参数从动作开始即被接管，而不是等到它第一次出现的时刻才接管。

每条参数曲线相邻关键点至少相隔 80ms，包括隐式零时刻到首个关键点。不同参数可以有相近的时刻；同一个全局时间只能出现一次，需合并到同一 `values` 对象。

## 4. 叠加、结束与中断

第一版只有一条前台动作轨道。宿主决定何时播放、替换或取消，AI 不能自设优先级，也不能通过无限时长锁住角色。

**基线 B(t)** 是当帧本地待机、表情、眨眼、视线和口型等既有控制器的合成结果。即使前台盖住某个通道，其基线仍继续计算。不能直接把上一帧前台写入值当成新基线，否则结束后会残留姿态或产生累积偏移。

- 前台控制期间：只覆盖本包涉及的参数；其余参数使用 B(t)。第一版不支持 AI 指定 add/multiply 混合。
- 正常结束或取消：每个被释放的参数记住当时前台值 P，在固定 200ms 内按 `lerp(P, B(t), smoothstep(progress))` 过渡，随后完全交回基线。归还基线不等于设为模型默认值。
- 新包替换：共有参数从当前合成值重新起步；新包独有参数也从当前合成值起步（包含可能尚未结束的旧释放）；旧包独有参数开始释放。已经在释放、且仍未被新包使用的参数继续原来的释放，不重置计时。
- 新包校验失败：当前动作和字幕保持不变。
- 重复取消是幂等操作：没有活动前台时，不重置正在进行的释放计时。

正常结束时 P 取曲线在 `duration_ms` 的值，释放进度按超出该时刻的时间计算；即使低帧率跨过结束点，也不从上一张已渲染帧的旧值重新启动 200ms。若已经跨过整个释放区间，直接使用当帧基线。主动取消则以最近一次已应用的物理前合成值为 P，从取消提交时开始释放。

在基线连续、范围有效且没有模型切换的前提下，前台接管、替换与释放保持参数值连续；暂不保证中断瞬间速度连续。既有表情等控制器若使基线瞬时跳变，释放中的最终值也可能跳变，应在基线层处理。smoothstep 每段的端点速度为零，动作可能带有停顿感；运动质感需要用实际素材验证，不能把弹簧与精确到达时间混为一个模式。

字幕在动作开始时显示全文，在 `duration_ms`、替换或取消时移除；新包没有字幕则清空旧字幕。字幕不跟随释放阶段延长。本版不承诺打字机、TTS、嘴形或词级音画同步。

## 5. 真实能力与参数所有权

原型能力表见 [natori-demo.v1.json](profiles/natori-demo.v1.json)。SDK 查询获得的值与拟议控制策略在该文件中分开记录。

| 真实参数 | 最小值 | 最大值 | 默认值 | 第一版拟议归属 |
| --- | ---: | ---: | ---: | --- |
| `ParamAngleX/Y/Z` | -30 | 30 | 0 | 前台可用候选，正负方向待视觉校准 |
| `ParamEyeLOpen/ROpen` | 0 | 1.3 | 1 | 前台可用候选；模型 EyeBlink 分组已核实 |
| `ParamMouthForm` | -3 | 1 | 0 | 前台可用候选；情绪映射未知 |
| `ParamMouthOpenY` | 0 | 1 | 0 | 本地保留，模型 LipSync 分组已核实 |
| `ParamBreath` | 0 | 1 | 0 | 本地待机保留 |

数值合法只证明动作可被执行，不证明表情自然、方向符合意图或组合没有瑕疵。Natori 未找到附带的 cdi3 名称说明文件；没有确认的含义标记未知。当前能力表只是选取八项参数的草案，不是模型的完整参数清单。

头发、衣摆、链条等 `physics3.json` 输出参数交给 Cubism 物理，禁止前台直接写入。模型中还存在多组手臂控制，但其姿态、显示切换及耦合关系未标定，因此本版不把它们宣称为通用“挥手”“转手腕”。其他未列入能力表的 ID 一律拒绝。

正式启用一个能力表前，应逐项确认含义与典型值，必要时缩小允许范围并添加组合约束。能力表、授权通道或模型文件发生变化时发布新的 `profile` 标识，旧动作不能直接沿用。宿主根据模型文件哈希、加载实例与能力表进行绑定；JSON 不能指定磁盘路径或加载模型。

## 6. 校验与接收规则

[JSON Schema](v0.1.schema.json) 使用 [Draft 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation) 做结构约束。它不能代替下述语义校验。

一次请求最多接收 32KiB UTF-8 JSON。先按严格 JSON 解析：拒绝重复对象键、NaN/Infinity、注释、代码围栏和尾随文本；再检查：

1. 版本受支持，profile 与当前活动实例绑定的能力表一致。
2. 参数全部在前台白名单中，原生值在该能力表允许区间内，整包不同参数不超过 16 个。
3. 时间严格递增、不重复，全部不超过 `duration_ms`；每参数关键点间隔满足 80ms 下限。
4. 请求仍属于当前会话、当前角色和当前响应代次。响应标识、去重、过期时间和取消代次由宿主保存，不让 AI 自己声明。

校验必须在提交前全部完成。已校验的包等待下一合成阶段时仍可能遇到取消或模型切换，因此提交时必须再次比较实例绑定、profile 与宿主代次；已过期的待提交包也要丢弃。任何一项失败就拒绝整包，返回具体字段路径及原因，由宿主决定是否让 AI 修正；不能只播放前半包或悄悄删除未知参数。运行时仍做最终范围夹取与有限数值检查，作为数值保护；若出现内部异常，撤销前台控制并回归基线，不把坏值写入 SDK。

换模型时递增宿主代次、取消旧控制并清除旧实例状态，迟到的旧响应直接丢弃。同一响应只提交一次。v0.1 等完整 JSON 到齐再播放，不执行半截对象或增量 token。

## 7. 给 AI 的最小上下文

模型不需要看到 Unity 类名、组件顺序、纹理或全部物理输出参数。给它当前 profile、可写参数的含义/范围/默认值、时序规则和本次动作意图即可。未知含义必须保留未知标记；不得让 AI 把猜测补成能力事实。

建议生成约束：

```text
你为当前角色生成一次短动作。只返回符合给定 Schema 的 JSON。
原样使用当前 version/profile；只使用提供的前台参数 ID 与原生范围。
at_ms 是到达目标的时刻，起点由本地当前姿态提供，不写 at_ms=0。
每个参数独立插值；省略不生成关键点；停留要重复同值关键点。
优先 3～8 个关键时刻和小幅变化，按意图安排准备、动作、停留与回收。
不要把未知参数映射成具体肢体动作。不要控制呼吸、口型开合或物理输出。
无法表达请求时，不编造参数；由上层对话返回能力不足说明，不提交动作包。
```

完整动作包例子见 [倾听姿态草案](examples/natori-listen.json) 与 [眨眼时序草案](examples/natori-blink.json)。它们已做结构与当前能力表数值校验，尚未由 DSL 播放器播放验证。

## 8. 最小实现边界

项目当前按原型阶段设计，只需三个模块：

| 模块 | 职责与数据归属 |
| --- | --- |
| `ActionContract` | 纯 C# 数据及校验逻辑；验证动作包、能力表与参数曲线 |
| `ActionPlayer` | 纯 C# 时钟/曲线/替换/释放状态；按帧输入时间和基线，输出前台合成值 |
| `Live2DActionAdapter` | 薄 MonoBehaviour；启动时解析真实 ID 到索引，维护基线、注入合成结果，连接字幕呈现 |

组合入口在角色加载完成后，按“读取模型能力 → 校验能力表 → 绑定适配器 → 接受动作”初始化。动作包是不可变数据；播放状态属于每个角色实例；能力表是本地配置。模型切换重新绑定，不用全局单例共享播放状态，也不需要事件总线。

当前 R4_1 的 `CubismUpdateExecutionOrder` 中，Look 为 700、Physics 为 800。可先把适配器作为 `ICubismUpdatable` 放在两者之间，例如 750：先采集既有控制器结果作为基线，再合成前台，随后让物理响应。这是针对当前 SDK 的接入方案，尚未实现；只写一个任意 `LateUpdate()` 不足以保证先后顺序。

适配器必须保证基线每帧独立恢复/计算，不能将前台覆盖结果再次保存为待机基线。接入已有 `CubismParameterStore`/Fade 时核对其恢复与保存时机；如采用自有基线缓存，要与现有机制避免双重恢复。物理写入完成后不要再次用前台覆写物理输出。

每帧不解析 JSON、不查找 GameObject、不构造参数字典；接收时编译为索引和关键点数组，播放时只求值。第一轮人工验收应覆盖：迟到响应、无效包不中断当前动作、稀疏插值、同值停留、替换共有/独有通道、结束回归运动中的基线，以及动画、眨眼和物理之间的所有权。

暂缓实现：动作队列、多前台轨道、语义动作库、任意自定义曲线、弹簧模式、增量流式追加、语音锚点、音素同步、道具、根节点位移/缩放、桌面宿主和小模型训练。它们需要单独契约，不能借用未定义的字段混入 v0.1。
